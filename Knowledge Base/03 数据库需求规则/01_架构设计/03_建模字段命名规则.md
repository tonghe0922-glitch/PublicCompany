# 建模、字段与命名规则

## 命名

- 数据库、Schema、表、字段统一 `lower_snake_case`；禁止拼音缩写和中文物理名。
- 主键统一 `id uuid`；外键统一 `<entity>_id`；业务单号统一 `business_no` 或明确对象号。
- 状态字段统一 `status`，状态值使用大写英文枚举；金额使用 `_amount`，时间使用 `_at`，日期使用 `_date`，布尔使用 `is_`/`has_`。
- 物理表不加 `t_` 前缀；流水表用 `_transaction`/`_ledger`；明细表用 `_item`；关系表语义化命名。

## 字段类型

| 业务类型 | PostgreSQL类型 | 规则 |
|---|---|---|
| 主键/外键 | uuid | 服务端生成UUID；禁止可猜测自增ID暴露到公网 |
| 金额 | numeric(18,2) | 禁止float/double；同时保存币种 |
| 比例/百分比 | numeric(9,6) | 数据库存0—1，展示层转换百分数 |
| 时间 | timestamptz | 统一存绝对时间；展示按Asia/Shanghai |
| 业务日期 | date | 不与时间戳混用 |
| 枚举 | varchar(32/64) | 受字典/Check约束；不可存中文展示值作为唯一语义 |
| 长文本 | text | 全文检索进入Search索引 |
| 动态结构 | jsonb | 必须带Schema版本；禁止把核心检索字段只放JSON |
| 手机/证件 | bytea密文 + varchar哈希 | 密文展示，哈希等值检索；禁止明文索引 |

## 主表与分表

1. 主表：一个聚合根一张，保存业务编号、状态、责任人、计划/实际时间和核心稳定字段。
2. 明细表：一对多项目、人员、物料、资源、金额明细拆行；严禁逗号拼接ID。
3. 流程表：只管理流程定义、实例、任务、迁移和动作，不重复保存业务明细。
4. 动态字段：低频、可配置字段进入类型化EAV `wf_submission_value`；高频查询字段升级为领域列并执行迁移。
5. 附件：统一进入对象存储与 `attachment_link`，按哈希防篡改。
6. 历史：状态和敏感变更只追加日志；禁止物理覆盖审计事实。

## 空值、默认值与删除

- `NOT NULL` 仅用于数据库层真正不可缺失的事实；流程早期可空字段在完成节点前由规则校验。
- 默认值只用于无歧义系统值，禁止用空字符串代替NULL。
- 业务表采用逻辑删除；审计、流水、签署、核销记录不得删除，只能冲销或作废。
